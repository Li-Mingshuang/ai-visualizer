1  为什么需要 RLHF？

监督微调（SFT）之后，模型的目标函数是"预测下一个 Token"——它学的是"什么话出现得多"，而不是"什么话是好的"。两者并不等价。

举例：回答"如何减肥"，SFT 模型可能生成流畅但空洞的文字，因为训练数据里这样的文字很多。RLHF 引入了人类偏好信号，让模型真正朝"有用"的方向优化。

核心问题：模型会说话，但不知道什么叫"好"。RLHF 的目标是把人类的偏好判断变成可微分的训练信号。

2  四个模型的分工

RLHF 训练中同时存在四个模型，各有职责：

  • Reference Model（冻结）：SFT 之后的原始模型，训练全程冻结，作为"锚点"防止 Actor 遗忘原有能力。

  • Actor Model（被训练）：真正学习的语言模型，从 Reference 初始化，PPO 不断更新它的参数。

  • Critic Model（被训练）：估算当前状态的预期奖励，用于计算优势函数 $A$，辅助 PPO 更新。

  • Reward Model（冻结）：预训练好的评分器，输入 Prompt+Response，输出标量奖励值，模拟人类偏好打分。

3  训练循环

每轮训练（一个 Episode）按以下步骤进行：

  • 从数据集采样一个 Prompt

  • Actor 自回归生成完整 Response（一次 Rollout），共 $T$ 个 Token

  • Reward Model 对 (Prompt, Response) 打分，得到末尾奖励 $r_T$

  • Critic 为序列中每个位置估算状态价值 $V(s_t)$，计算 优势 $A_t$

  • 计算 Actor 相对 Reference 的 KL 散度，作为惩罚项加入奖励

  • 用 PPO 算法多轮迭代更新 Actor 和 Critic 参数

4  优势函数：谁该被加强

奖励 $r_T$ 只在序列末尾给出，但一个 Response 由 $T$ 个 Token 组成，我们需要知道"哪个 Token 的选择对最终结果有贡献"。这就是优势函数 $A_t$ 的作用。

基础定义

Critic 输出的价值函数 $V(s_t)$ 是对"从当前位置出发，能获得多少期望奖励"的估计。优势 $A_t$ 衡量实际结果比估计好多少：

$$A_t = R_T - V(s_t)$$
基础优势估计（实际回报 − 基线）；$R_T$ 为序列末尾的实际回报（RLHF 中奖励仅在末尾给出）

$A_t > 0$：这个 Token 的选择比预期好，PPO 应该提高它的概率。$A_t < 0$：比预期差，应该降低它的概率。$A_t$ 的绝对值决定更新力度。

GAE（广义优势估计）

实际中更常用 GAE（Generalized Advantage Estimation），它在"方差低但有偏"与"方差高但无偏"之间通过 $\lambda$ 做权衡：

$$A_t^{\text{GAE}} = \sum_{l=0}^{\infty} (\gamma \lambda)^l \,\delta_{t+l}$$ $$\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t) \quad \text{（TD 误差）}$$
λ=0 时退化为单步 TD；λ=1 时等价于蒙特卡洛回报

优势在序列中的分布

下方展示了一个回答序列中各 Token 的优势值。颜色越绿表示这个 Token 的选择越优于预期，越红则相反。PPO 的目标就是提高绿色 Token 的概率，降低红色的。

交互 · Token 级优势分布

悬停查看每个 Token 的 A 值。颜色深浅反映优势大小，正优势（绿）会被加强，负优势（红）会被削弱。

关键理解：优势函数把"序列整体奖励"分解到每个 Token 上，让 PPO 知道"这条序列里哪些决策是好的"，而不是笼统地对整个序列奖惩。

5  PPO Clipping：限速器

强化学习里，策略更新步子太大容易翻车——新旧策略差太多，之前采集的数据就失去参考价值，训练不稳定。PPO 用 Clipping 直接在目标函数里加限速器。

定义概率比 $r_t(\theta) = \frac{\pi_\theta(a_t|s_t)}{\pi_{\theta_\text{old}}(a_t|s_t)}$，它衡量当前策略和上一轮策略对同一动作的概率之比。PPO 的裁剪目标为：

$$L^{\text{CLIP}}(\theta) = \mathbb{E}_t \left[ \min\!\left( r_t(\theta)\,A_t,\ \operatorname{clip}(r_t(\theta),\,1{-}\varepsilon,\,1{+}\varepsilon)\,A_t \right) \right]$$
ε 通常取 0.1~0.2；取 min 保证目标是保守的下界

取 $\min$ 的作用：当 $A_t > 0$（好动作），$r_t$ 超过 $1+\varepsilon$ 后目标封顶，不再奖励更大的概率比；当 $A_t < 0$（坏动作），$r_t$ 低于 $1-\varepsilon$ 后目标托底，不再惩罚更小的概率比。两个方向都对过激更新踩刹车。

6  KL 散度约束：防止跑偏

即使有 Clipping，多轮更新后 Actor 仍可能越走越偏——开始忘记原有能力，或者专门生成能骗过 Reward Model 但对人类无意义的输出（奖励 Hacking）。

解法是在每个 Token 的奖励里直接扣除 KL 惩罚：

$$r_t^{\text{adj}} = r_t - \beta \cdot \underbrace{\log \frac{\pi_\theta(a_t|s_t)}{\pi_{\text{ref}}(a_t|s_t)}}_{\text{per-token KL}}$$
$\beta$ 越大 → 对偏离 Reference 的惩罚越重；实践中常动态调整

$\beta$ 的权衡：$\beta$ 太小，Actor 跑偏，奖励 Hacking；$\beta$ 太大，Actor 被 Reference 锁住，学不到新东西。实践中用自适应 KL 控制，让 KL 维持在目标值附近。

7  参数更新：Actor 和 Critic

一次 Rollout 采集到数据后，PPO 会对同一批数据做多次（通常 4 轮）小批量梯度更新：

Actor 更新

对 Actor 做梯度上升（最大化目标），同时加入熵正则化防止策略退化成确定性输出：

$$L^{\text{Actor}} = L^{\text{CLIP}}(\theta) + c_{\text{ent}} \cdot H(\pi_\theta)$$
$H(\pi_\theta)$ 为策略熵；$c_{\text{ent}}$ 通常取 0.01 量级；KL 惩罚已在第 6 节的调整后奖励 $r_t^{\text{adj}}$ 中体现，不在此项重复计入

Critic 更新

Critic 通过最小化预测价值与实际回报之间的均方误差来更新，让 $V(s_t)$ 越来越准：

$$L^{\text{Critic}} = \mathbb{E}_t\!\left[\left(V_\phi(s_t) - V_t^{\text{target}}\right)^2\right]$$
$V_t^{\text{target}} = V(s_t) + A_t^{\text{GAE}}$（GAE 优势 + 当前价値估计），等价于折扣回报的 TD 目标估计

两个损失分别反向传播，Actor 和 Critic 使用各自的优化器更新。实践中也有共享底层参数的设计（节省显存），此时两个损失加权合并。

为什么要多轮更新同一批数据（PPO 的 Epoch）：收集一批 Rollout 的代价很高（需要推理），PPO 允许对同一批数据更新多次，提高数据利用率。但更新轮数不能太多，否则 $r_t(\theta)$ 偏离 1 太远，Clip 就失去意义了。

8  训练动态

一次成功的 PPO RLHF 训练，四条曲线应呈现：奖励上升、KL 受控、熵缓慢下降但不崩塌、Clip 比例稳定。
